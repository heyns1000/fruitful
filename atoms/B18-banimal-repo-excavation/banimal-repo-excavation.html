How this was read

No sampling, no trusting a README's description of itself.

git ls-files for the full tracked list (191 files — the working tree shows 452MB but almost all of that is .git history and the dist/ build output's image assets), then every config file, every migration, every worker route, the WordPress plugin's core classes, and the loose top-level documents read in full. package-lock.json and the built dist/assets/*.js bundles were treated as generated noise and skipped; everything with actual authored content was opened.

One live finding came out of this pass rather than staying a note: Vito_Stroller.html (repo root) was an unrelated stroller-import cost model with real supplier links, sitting in the servable path and referenced by a top-level assets manifest — archived to archive/Vito_Stroller.html.archived and HTML-escaped inert as part of this session. Everything else below is reported, not changed.

Orientation

Four layers, one Worker

Nothing in the repo names these as separate systems — this is what the code actually does, read layer by layer.

1 · The Banimal storefront

real, deployed

100% organic cotton babygrows and bibs, South Africa. Real product catalog in dist/sitemap.xml (babygrows in 4 colors × 3 age ranges, 8 bib designs), real checkout intent via Paystack (orders.ts), real BobGo v2 shipping integration with a live sandbox/production switch (delivery.ts), a giving model that donates 15.01% of every pre-tax sale (giving.ts, tiers GIVE-BIB → GIVE-LAYETTE).

src/worker/routes/{orders,delivery,giving,email,coupons,analytics}.ts · migrations 0002, 6, 7

2 · The brand vault (FAA / HSOMNI9000 / Seedwave)

real schema, seeded data

A completely separate multi-tenant "brand governance" system riding in the same D1 database and the same Worker. migrations/2.sql seeds three named systems with real counts: FAA™ — 7,344 brands, "Global Trade & Governance"; HSOMNI9000 — 6,219 brands, "Advanced AI & Mesh Network"; Seedwave — 150 brands, "Premium Sovereign Brands". Five tiers (Sovereign, Dynastic, Operational, Market, VaultMesh) and a vault_mesh_id field tie individual brand rows into whatever the wider mesh is. None of this touches babygrows — it's routed at /api/brands, /api/systems, /api/tiers, entirely separate from the storefront's order/payment path.

src/worker/routes/brands.ts + inline handlers in index.ts · migrations 1.sql, 2.sql

3 · The Banimal™ Connector (this session's work)

real, this session

The WordPress↔Worker bridge built across PRs #14–#23: a thin, HMAC-signed plugin client (wordpress-plugin/banimal-ecosystem-connector/), the /api/wp/events ingestion endpoint with idempotent event storage and WooCommerce order-state mapping (wp-bridge.ts), and the /api/brand-guide endpoint serving the verified Sam Fox™ CI Guide. This is the one layer with a matching Claude Code skill (banimal-connector/skills/samfox-ci-guide/) and four maintained reference documents in docs/.

src/worker/routes/{wp-bridge,brand-guide}.ts · wordpress-plugin/ · docs/

4 · Concept dashboards & one-off documents

flavor / unrelated

22 React pages under src/react-app/pages/ — BaobabPortal ("Gateway to the 1000-Year Ecosystem"), EcosystemDashboard ("GhostTrace™"), Omnigrid, NexusNair, ThesisDebug — read as AI-generated admin-dashboard concept art layered over the same domain names, not wired to real backend logic beyond a handful of stat cards. Alongside them, three loose top-level documents with no connection to any of the above: banimal_api_connector.html ×2 (a mocked API-monitor referencing "FAA Inline Verification Mandate P_INV-001" protocols), a full frozen snapshot of the app from 2025-12-31 zipped at repo root (Banimal Store Integration Guide.zip), and the now-archived Vito_Stroller.html.

Inconsistencies worth knowing before dispatch

Nothing here was fixed — each one only touches files outside what was asked for today.

high
Two different giving rates for the same thing

giving.ts computes the real donation rate as 0.1501 (15.01%, matches the welcome email copy). orders.ts's own inline giving-allocation insert hardcodes 0.02 with the comment // 2% giving — a live, uncorrected contradiction in the actual checkout path.

high
Three order-reference formats for one concept

BAN-<nanoid> (orders.ts), TXN_<nanoid> (payments.ts), WC-<wc_order_id> (wp-bridge.ts) — three ID schemes for what the schema treats as one orders table, with no visible reconciliation between them.

medium
Session tokens aren't signed

auth.ts issues btoa(JSON.stringify({...})) as a bearer token — trivially forgeable, not a JWT. The code's own comment says "in production use a signed JWT."

medium
Coupon usage counters don't persist

coupons.ts tracks uses on a module-level object in memory. Every Cloudflare Worker isolate restart (routine, frequent) resets every code's usage count to zero — maxUses is not actually enforced in production.

medium
Domain split between .co.za and .faa.zone

SEO surface (manifest.json, sitemap.xml, robots) targets banimal.co.za; transactional email templates (welcome, order confirmation, order update) link to banimal.faa.zone/shop and /track/. Both are live CORS origins in index.ts, so neither is obviously wrong — but a customer following an email link lands on a different domain than the one Google indexes.

low
Brand-vault seed count vs. the figure already flagged this session

7,344 + 6,219 + 150 = 13,713 seeded rows. docs/connector-preview.html's routing table already flags an unrelated "13,413 brands" figure from the old Perplexity-dump research as unreconciled and unverifiable. These are two different numbers from two different sources — noted here so they aren't accidentally merged into one figure later.

low
Frozen 2025-12-31 snapshot committed as a zip

Banimal Store Integration Guide.zip at repo root contains a 63-file, near-complete copy of the app as it existed on 2025-12-31 — a time capsule sitting in version control rather than a release artifact or a git tag.

Not investigated further

Loose ends, named so they aren't lost

  • The top-level assets file (45 bytes, plain text — not a directory) lists two servable paths: /Vito_Stroller.html (now archived, so this reference is dangling by design) and /images/New_stroller.png. What actually reads this manifest was not identified.
  • banimal_api_connector.html and banimal_api_connector_15-01.html (two near-identical copies) reference an "FAA Inline Verification Mandate" with protocol IDs like P_INV-001 — governance-protocol lore tied to the FAA™ brand-vault system, not explained anywhere else in the repo.
  • 22 React dashboard pages (BaobabPortal, Omnigrid, OmnigridEngine, NexusNair, ThesisDebug, EnterprisePayroll, …) were not read line-by-line — confirmed by title/heading grep to be concept-dashboard UI over the same domain names, not verified feature-by-feature.
  • notifications.ts's push-send path needs a real VAPID-JWT signing implementation before it can work against real browser push endpoints — currently a plain POST.
