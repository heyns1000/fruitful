What is the Omnigrid engine?

Think of it as the grid's nervous system

Right now, keeping 100+ repos in sync is a manual job. Someone has to notice a branch is behind, open a PR, wait for review, merge it. The Omnigrid Automation Engine does that automatically — every 9 seconds it checks the pulse of the network, finds branches that have drifted, and brings them back in line. Think of it like a silent operations team that never sleeps.

It also handles the paperwork: approving Copilot's clean code suggestions, merging low-risk content updates, flagging anything that needs a human eye. The goal is that you only get interrupted for decisions that actually need you — not routine housekeeping.

Currently, the engine's main guardrail (ENGINE_ENABLED) is set to false. Every workflow checks this flag first. Nothing runs. This debrief is the step before flipping it.

The 4-layer safety architecture

1 Allowlist Gate
Only named repos can be auto-merged
The master config file holds an explicit list of repos the engine is allowed to touch. Any repo not on the list is invisible to the automation — it can't be merged, synced, or modified. You control the list, we don't change it without your sign-off.
ONE_GRID_TIEKIEBOKS.json → repo allowlist
2 Branch Pattern Gate
Auto-merge only on claude/* branches
Even within an allowed repo, the engine only acts on branches that follow the claude/* naming pattern. A Copilot PR that targets main directly bypasses this protection — so it stays in your hands, not the engine's.
branch: "claude/*" → eligible · "main" → human only
3 Repo-Type Gate
Content repos auto, core infra needs you
The 33 Seedwave content sites (agriculture, banking, health, etc.) are low-risk — a bad merge there changes a webpage, not a payment system. Core infrastructure (banimal, ecosystem-governance-sentinel, vaultmesh, claimroot) requires human approval before anything merges.
seedwave.faa.zone/* → AUTO · banimal|sentinel|vaultmesh → HUMAN
4 CI Gate
Each repo's own tests are the final word
Even if layers 1–3 all say "auto-merge", the PR still has to pass the repo's own CI checks — tests, linting, typechecks. The engine never merges a red build. This is the last line of defence and the only one that runs inside the repo itself.
conclusion: "success" required · failure → held for review

What we are NOT changing

  • ENGINE_ENABLED stays false until you explicitly set it to true in GitHub → Settings → Variables → Actions.
  • No repo's main branch is touched by the engine directly — only PRs on claude/* branches get auto-merged.
  • banimal, sentinel, vaultmesh, claimroot require your manual approval on every PR, regardless of branch name.
  • The allowlist in ONE_GRID_TIEKIEBOKS.json is not changed by us — you control which repos are in scope.
  • All 20 existing workflows continue checking the ENGINE_ENABLED flag at the top of every run — one toggle pauses the entire grid instantly.

What happens after you approve?

We update ONE_GRID_TIEKIEBOKS.json with the 4-layer rules, then you set ENGINE_ENABLED=true in GitHub. The next scheduled run (top of the hour) is the first live pulse.
