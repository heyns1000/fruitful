Methodology & a correction made mid-audit

What broke, and how it was caught

The GitHub API's bulk pull-request list endpoint returned merged: false for every one of the 100 PRs fetched — including PR #117, which a direct per-PR fetch confirmed was genuinely merged (merged: true, merged_by: heyns1000). Trusting the bulk field would have produced a false "0 of 100 PRs ever merged" headline.

  • Ground truth for "did this land on main" is git log origin/main --merges (real merge commits) plus a scan for GitHub's (#N) squash-merge commit-message convention — not any PR-list API field.
  • Branch/status pairing otherwise uses the bulk PR list's state field (open/closed), which is reliable — only merged was not.
  • Branch count (77 incl. main) and file-count (90) are read directly from this session's clone and the GitHub branches API on 2026-09-03 — not carried over from the README's own "74 branches" figure, which is now a few branches stale.
